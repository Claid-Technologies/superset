## Client

```ts
import Superset from '@superset_sh/sdk';

const client = new Superset({
  apiKey: 'sk_live_…',
  organizationId: '…',
  // optional:
  baseURL: 'https://api.superset.sh',
  timeout: 60_000,
  maxRetries: 2,
  logLevel: 'warn', // 'off' | 'error' | 'warn' | 'info' | 'debug'
});
```

### How calls reach a workspace

`workspaces.*`, `tasks.*`, and `organization.*` call the Superset API. `terminals.*` and `agents.create` run inside a cloud workspace's sandbox: before the first such call for a workspace, the SDK asks the API for a ticket for the sandbox's last known address. It caches the ticket and sends calls through Superset's gate with it; after a call fails it asks the API to wake the sandbox, which also refreshes the address, so a script follows a sandbox that stopped or moved. Your API key is only ever sent to the API.

The workspace must be `ready`. Asking for a ticket to a `provisioning` or `failed` workspace fails with a `412`. Right after a workspace turns `ready` its checkout may still be arriving, so a terminal or agent call can fail briefly; retry it.

### Telemetry

The SDK reports one `sdk_method_called` event per resource call: the method name (for example `tasks.list`), SDK version, runtime, whether the call succeeded, and how long it took. Request and response data are never included. The report is sent after your call settles and is best-effort, so it cannot slow down or fail a call. Set `SUPERSET_TELEMETRY=0` to turn it off.

## tasks

### `tasks.create(body)`

Create a task.

```ts
const task = await client.tasks.create({
  title: 'Wire up auth',
  description: 'See SUPER-100',
  priority: 'high',          // 'urgent' | 'high' | 'medium' | 'low' | 'none'
  assigneeId: '<uuid>',      // optional
  statusId: '<uuid>',        // optional, defaults to first backlog status
  estimate: 4,               // optional, story points
  dueDate: '2026-12-31',     // optional, ISO date
  labels: ['bug'],           // optional
});
```

Returns a `Task`.

### `tasks.list(params?)`

List tasks with rich filters. All filters AND-combine.

```ts
const tasks = await client.tasks.list({
  assigneeMe: true,          // tasks assigned to you
  creatorMe: true,           // tasks you created
  priority: 'high',
  statusId: '<uuid>',
  assigneeId: '<uuid>',      // someone else's tasks
  search: 'auth',            // substring of title
  limit: 50,                 // max 500
  offset: 0,
});
```

Returns `Array<TaskListItem>`. Each row is a `Task` denormalized with `assigneeName`, `assigneeImage`, `creatorName`, `creatorImage`, and `statusName` so you don't need follow-up calls for display.

### `tasks.retrieve(idOrSlug)`

Look up a single task by id or slug.

```ts
const task = await client.tasks.retrieve('SUPER-172');
if (!task) throw new Error('not found'); // returns null when missing
```

Returns `Task | null`.

### `tasks.update(body)`

Patch a task.

```ts
const task = await client.tasks.update({
  id,
  priority: 'urgent',
  statusId: '<uuid>',
  prUrl: 'https://github.com/…',
});
```

Returns the updated `Task`.

### `tasks.delete(id)`

Soft-delete a task.

```ts
await client.tasks.delete(id);
```

### `tasks.statuses.list()`

List the task statuses (workflow states) configured for the active organization, in display order. Useful for resolving status ids before [`tasks.create`](#taskscreatebody) or [`tasks.update`](#tasksupdatebody).

```ts
const statuses = await client.tasks.statuses.list();
const todo = statuses.find((s) => s.type === 'unstarted');
```

Returns `Array<TaskStatus>`. Each entry is `{ id, name, color, type, position }`.

## workspaces

Cloud workspaces in the active organization. Each is a sandbox started from an environment; the environment's repositories are its checkouts. Environments are created in the desktop app under **Settings → Environments**.

Every workspace method requires cloud workspaces to be enabled for your account, and returns `403` otherwise.

A `CloudWorkspace` carries `id`, `organizationId`, `name`, `branch`, `status` (`'provisioning' | 'ready' | 'failed'`), `environmentId`, `createdByUserId`, `createdAt`, `updatedAt`, and the sandbox fields `provider`, `providerSandboxId`, `sandboxUrl`, and `hostVersion`. Timestamps are ISO strings.

### `workspaces.list({ search? })`

List the organization's cloud workspaces, newest first. Provisioning and failed workspaces are included, so check `status`. `search` is a case-insensitive substring match on name or branch.

```ts
const workspaces = await client.workspaces.list();
const ready = workspaces.filter((w) => w.status === 'ready');
```

Returns `Array<CloudWorkspace>`.

### `workspaces.retrieve(id)`

Look up one cloud workspace by id.

```ts
const workspace = await client.workspaces.retrieve(id);
if (!workspace) throw new Error('not found'); // returns null when missing
```

Returns `CloudWorkspace | null`.

### `workspaces.create({ environment?, name?, branch?, agent?, prompt?, model?, effort? })`

Create a cloud workspace. Provisioning runs in the background, so this returns as soon as the workspace is recorded, with `status: 'provisioning'`. Poll [`workspaces.retrieve`](#workspacesretrieveid) until it is `ready` before creating terminals or agents in it.

- `environment`: environment id or name (case-insensitive). Omit it to use the first environment with repositories. An environment without repositories can't start a workspace; the SDK throws a `SupersetError` naming the ones that can.
- `name`: omit it to have a name generated from `prompt`.
- `branch`: omit it to use the primary repository's default branch.
- `agent` and `prompt`: a built-in agent (`'claude'` or `'codex'`) to launch on first boot, and what to tell it. Each requires the other.
- `model` and `effort`: agent-specific launch overrides. Both require `agent`.

```ts
const workspace = await client.workspaces.create({
  environment: 'web',
  name: 'fix-login-flake',
  branch: 'fix/login-flake',
  agent: 'claude',
  model: 'sonnet',
  effort: 'high',
  prompt: 'Find why the login test is flaky, fix it, and push the branch.',
});
```

Returns the `CloudWorkspace`.

### `workspaces.update(id, { name })`

Rename a cloud workspace.

```ts
await client.workspaces.update(id, { name: 'fix-login-flake-v2' });
```

Returns the updated `CloudWorkspace`.

### `workspaces.delete(id)`

Delete a cloud workspace and tear down its sandbox, which stops its billing.

```ts
const { deleted } = await client.workspaces.delete(id);
```

Returns `{ deleted }`, which is `false` when no workspace has that id.

## agents

### `agents.create({ workspaceId, agent, prompt?, resumeSessionId?, model?, effort? })`

Launch an agent session in a `ready` cloud workspace, in a fresh terminal session.

`agent` is a built-in agent installed in the sandbox (`'claude'` or `'codex'`). `prompt` is optional when `resumeSessionId` restores a previous run of the same agent. `model` and `effort` are agent-specific launch overrides; omit them to use the agent's defaults. Unsupported values fail before launch with a message naming the supported ids.

Returns `{ kind, sessionId, label }`. `sessionId` is the terminal id, so [`terminals.read`](#terminalsread-workspaceid-terminalid-maxlines-) and [`terminals.send`](#terminalssend-workspaceid-terminalid-text-submit-) work on it.

```ts
const { sessionId } = await client.agents.create({
  workspaceId: '<uuid>',
  agent: 'claude',
  model: 'sonnet',
  effort: 'high',
  prompt: 'Audit the login flow for race conditions.',
});
```

## terminals

Terminal (PTY) sessions inside a `ready` cloud workspace.

### `terminals.create({ workspaceId, command?, cwd? })`

Create a terminal session. Pass `command` to run a shell command, or omit it to open an interactive shell. `cwd` defaults to the workspace checkout. Returns `{ terminalId, status }`.

```ts
const { terminalId } = await client.terminals.create({
  workspaceId: '<uuid>',
  command: 'bun install && bun test',
});
```

### `terminals.list({ workspaceId })`

List the live terminal sessions in a workspace. Returns `{ sessions }`, each `{ terminalId, workspaceId, createdAt, exited, exitCode, attached, title }`.

### `terminals.send({ workspaceId, terminalId, text, submit? })`

Write text into a running terminal, such as a follow-up message to an agent. Multi-line text lands as one paste. `submit` (default `true`) presses Enter after it. Returns `{ terminalId, submitted }`.

```ts
await client.terminals.send({
  workspaceId: '<uuid>',
  terminalId: sessionId,
  text: 'Also add a regression test.',
});
```

### `terminals.read({ workspaceId, terminalId, maxLines? })`

Read a terminal's current screen and recent scrollback as plain text. For an agent this is its rendered output. `maxLines` caps the rows returned from the bottom. Returns `{ terminalId, cols, rows, text }`.

```ts
const { text } = await client.terminals.read({
  workspaceId: '<uuid>',
  terminalId: sessionId,
  maxLines: 40,
});
```

### `terminals.close({ workspaceId, terminalId })`

Close a terminal, killing its process and any agent running in it. Returns `{ terminalId, status }`.
