Terminal links stop where they should.

The next log prefix was becoming part of the URL. The updated provider respects explicit newlines, uses actual terminal cells for its clickable range, and adopts VS Code’s URL parsing rules.

The reported bug, reproduced

The same three-line log was written to real browser xterm terminals. Actual mouse hover and click delivered the malformed URL before the change and the correct URL afterward.

Before

http://localhost:3001/sloyd-web:dev:localhost:sloyd-web:dev:localhost

Clickable range: column 41, row 1 → column 24, row 3.

After

http://localhost:3001/

Clickable range: column 41, row 1 → column 62, row 1.

What changed

1. Explicit newlines stop links

Removed the heuristics that joined a URL ending in / to the next line’s log prefix, indented prose, filenames, or numbers. Only xterm’s isWrapped metadata permits joining rows.

2. Exact terminal-cell ranges

The inclusive end coordinate now points to the final URL cell. Mapping accounts for wide characters, emoji, combining marks, and the empty cell left when a wide character wraps early. A real separating space is preserved.

3. Upstream parsing

Adapted VS Code’s state machine for quotes, Markdown emphasis, IPv6, Unicode punctuation, and bracketed paths. Retained balanced nested delimiters and trailing punctuation handling, validated HTTP(S) URLs, and preserved their original spelling.

4. Bounded, consistent wrapping

URLs spanning more than three rows work from each row. The 4,096-code-unit limit budgets up to two terminal cells per unit, so long CJK URLs are not truncated. No stale coordinates are cached across resize.
